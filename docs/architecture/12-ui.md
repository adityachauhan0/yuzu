# UI

The app looks like [design/product-handoff/index.html](../../design/product-handoff/index.html). Geometry, color, type, icons, mascots, motion, and component anatomy are copied from that file and from [DESIGN.md](../../design/product-handoff/DESIGN.md). A screen that is not in the handoff does not get a new visual language. It is built from controls that file already draws: `.settings-row`, `.settings-toggle`, `.settings-callout`, `.settings-plain-button`, `.popover`, `.skill-row`, `.skill-dialog`, `.code-model-row`, `.code-heatmap`.

Names in the prototype that point at Claude, Anthropic, a sample model, or the owner’s machine are reference ids. They are not product copy. The table below is the substitution. Everything else on screen, including **Yuzu is on-device AI. its not the best. Please double check responses.**, is kept character for character.

## Golden line

- One window. Sidebar `--sidebar-width: 256px` (232px at `1024px`, drawer at `768px`). Content column `--content-width: 806px`. Scheduled and Customize use their wider page widths from the CSS.
- Colors only from `:root` and `:root[data-theme="light"]`. Dark starts pressed. Theme swap is `data-theme` plus every `img[data-mascot]`.
- Faces the prototype actually paints: UI `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`; display and assistant prose `Georgia, "Times New Roman", serif`; code `ui-monospace, SFMono-Regular, monospace`. No remote font.
- Icons are the inline symbols. `.icon` 18px, `.small` 16px, `.tiny` 14px, stroke 1.65, round caps.
- Mascots stay the supplied SVGs, full frames, `data-mascot="cowork"` or `"code"`. Account mark 28px, welcome mark 42px, Code composer mascot 56px and 16px from the right of the input.
- Hover and toggle motion is 180ms `--ease: cubic-bezier(.2,.8,.2,1)`. The sidebar drawer is 220ms on the same curve. `prefers-reduced-motion: reduce` collapses those durations, as the stylesheet already does.
- Breakpoints stay 1240, 1024, 768, 620, and 480. The inspector overlays at 1240. Settings stacks at 620.

## Shell

Sidebar, top to bottom, as drawn:

1. Traffic lights, collapse sidebar, search.
2. **Cowork** and **Code**. Code is the initial mode. Switching back to Cowork returns to the last Cowork page.
3. **New**, **Projects**, **Artifacts**, **Scheduled**, **Customize**.
4. **Pinned**. Hidden when nothing is pinned. A pinned project and a pinned task use the buttons already in the sidebar.
5. **Tasks**. Real sessions. The empty list uses the existing toast **Recent tasks appear here after you send one.** only when the user hits the task-options button with an empty list. The list itself stays blank.
6. Account row: cat, **Yuzu Beta**, chevron. Menu: **Yuzu Beta Version 0.0.1**, **Settings** (⌘,), **Language**, **Inference configuration**, **View changelog**, **Learn more**, **Sign out**.

Account actions:

- **Language** opens the same popover with one checked row, **English**.
- **Inference configuration** opens Settings on Developer, scrolled to the Inference heading.
- **View changelog** opens `.skill-dialog` with the app version and the release notes.
- **Learn more** opens the project docs in the browser.
- **Sign out** toasts **Yuzu runs on this Mac. There is no account to sign out of.** The toast component is the one already on the page.

Search is the existing dialog **Search this workspace**. Results are the same result buttons, over pages, session titles, skill names, and settings tabs. Empty copy stays **No matching items.** Settings’ own search field filters that sidebar’s tab labels in place.

## Code

Heading, usage tabs **Overview** and **Models**, periods **All**, **30d**, **7d**. Metric order: Sessions, Messages, Total tokens, Active days, Peak hour, Favorite model. The heatmap is 26 columns, 4px gap, 2px radius, `.level-1` and `.level-2` from real active days. Models lists each model that has token counts as a `.code-model-row`; the trailing label is the share of tokens, and the top row’s label is **Favorite model**.

**Local** stays the environment chip. It is the only environment, and it stays in the selected style. It does not open a cloud picker.

**Select folder…** is the working project for the next Code prompt. After a choice, the button shows the folder name in `.code-folder-name`.

Composer placeholder **Describe a task or ask a question**. **+** is **Add context** and uses the same menu as Cowork’s add menu: **Attach a file**, **Choose a project**. A chosen file is listed in muted 13px type under the composer, the same color as `.thread-note`, and is part of the prompt context. **Manual** is a toggle on the existing button. Pressed means the permission mode asks before edits and shell. Unpressed means accept-edits, writes allowed, shell still asks. See [Permissions](05-permissions.md).

The model button opens the same popover anatomy: one button per installed tool-capable model at High, Medium, and Low. Effort is `ReasoningEffort` on the next turn.

Sending stays on this page, fills `.code-task-preview` with the prompt, and adds a task row. The drain is the same one Cowork uses, with this folder as the project.

## Cowork

### New task

**Good Evening, {name}**, cat mark, composer **How can I help you today?** Tools: add, model and effort, project. Project menu is **No project** plus known project folders. Ideas stay **Send me a daily briefing**, **Organize my inbox**, **Customize Cowork for me**. An idea fills the composer and does not send. Empty submit toasts **Write a task to get started.** Enter sends, Shift-Enter breaks a line. A sent task opens the thread.

### Projects and Artifacts

Same centered serif panel and **New task** button.

- A selected project: title is the folder name, description **Your project is ready for new tasks.**, detail **Select the project below to start a task in this workspace.**
- No project: title **No project yet**, description **Your project is ready for new tasks.**, detail **Choose a folder to start a task in this workspace.**
- Artifacts empty: title **No artifacts yet**, description **Artifacts created from tasks will appear here.**, detail **Start a task to create an artifact in this workspace.**
- Artifacts that exist are `.skill-row` buttons in that panel: file name, and the task that wrote it.

### Thread

Composer **Write a message…**. The on-device disclaimer under it is unchanged.

Bubbles, in the styles already defined: user, assistant intro, assistant reply (serif, copy button, cat mark), and the activity line for tool settlement (**Updated tasks, ran N commands**, with the real count). The Greeting demo is not seeded.

Transcript view does not add a layout. **Normal** is the bubbles above. **Thinking** adds the stored reasoning in the assistant reply’s type. **Verbose** also shows tool name and arguments on the activity line. Default comes from Code settings. The thread title button opens the popover the prototype left empty (`#thread-title-items`), with rows in the account-menu style: **Rename**, **Pin**, **Normal**, **Thinking**, **Verbose**, **Delete**.

Inspector **Task details**, same three sections:

- **Progress** — the step marks already drawn. Completed steps are the session todos that finished. The help line stays until there is a todo.
- Project — the session’s folder name, **Open** on the folder button, files created this task. Help line **View and open files created during this task.** stays when the list is empty.
- **Context** — tool calls and referenced files. Help line **Track tools and referenced files used in this task.** stays when empty.

Wide: the inspector takes a column and the thread recenters. At 1240 and below it overlays, and Escape or the existing close path dismisses it.

### Scheduled

Unchanged chrome: title, search, sort **Next run** / **Name**, **New task** with **Create scheduled task** and **New task**, the awake sentence, **Keep awake** (`.awake-switch`). **Keep awake** holds an app-nap assertion while any schedule is armed. Empty state **No scheduled tasks yet.** and the six examples stay. An example fills the create dialog. **Create task** uses `.skill-dialog`’s sibling, the schedule dialog already in the page. A row replaces the empty state. Firing a schedule starts a drain only while the app is running and the machine is awake.

### Customize

Banner stays, with **Skills teach Yuzu how you work.** Tabs **Skills**, **Connectors**, **Plugins**. Search, filter, sort, and **Add** stay.

Skills rows are real skills. Heading **From Yuzu · {n}** and, when the user has any, **From you · {n}**. Filter **All sources** plus those two sources. **Create skill** is the existing dialog (name, description) and writes a project skill. A row opens the same dialog in detail mode: title, description, **Close**.

Connectors and Plugins do not use the prototype’s “not provided in the reference” sentence. They use the tab panel that is already there.

- Connectors lists MCP servers as `.skill-row` (name, status in the meta line). Empty callout, in `.settings-callout` color on that panel: **No servers added.** **Add** opens Settings → Developer at the config field.
- Plugins uses the same empty callout: **No plugins yet.** There is no plugin gallery in this design, and no second card style.

## Settings

Sidebar groups and tab labels stay: General, Privacy, Usage, Code, Cowork, Import & export, System, Developer, Skills, Connectors, Plugins.

**Code.** Code appearance as drawn: light theme GitHub Light / Default Light, dark theme GitHub Dark / Default Dark, both `greet` previews fixed (they are samples of code color, not app chrome). **Code font** placeholder **e.g. JetBrains Mono**. **Interface font**: System (pressed), Serif, OpenDyslexic. **Transcript text size** Small / Medium / Large, Medium pressed. **Transcript width** Narrow / Medium / Wide, Narrow pressed. Narrow is the 806px column. Medium and Wide step that max up inside the same centered column, without changing the sidebar. **Default transcript view** Normal / Thinking / Verbose, Normal pressed. **Sessions** lists Code sessions as `.code-model-row` (title, project). Empty callout **No sessions yet.**

**General.** Profile avatar and **What best describes your work?** (Select, Engineering, Design, Research, Writing, Other). **Instructions for Yuzu**, same field. Theme System / Light / Dark, Dark pressed, the icon segment already there. Chat font Serif / System. Motion System / Reduced, the existing pair. **Response completions** is the existing switch; on, it posts a notification when a drain finishes.

**Cowork.** Files path and **Change**. Trusted folders: the existing explanation, with “Claude” read as Yuzu, **Manage**, and **No trusted folders added.** A trusted folder is a saved path allow. Global instructions **Edit** opens the inline field already in the panel. Memory: the switch, default on, and the two callouts. With the name swapped, they read that Yuzu saves memories on this device, and **No memories yet. Yuzu will add entries here as you work together.**

**Developer.** **Local MCP servers**, **No servers added**, **Edit config**, **Developer docs** (opens the MCP docs in the browser). The config textarea is the `mcp_servers` JSON. Under an **Inference** heading, three `.settings-row`s: engine version (uzu), context length, and the sampling defaults for the loaded model. This is the destination of **Inference configuration**.

**Privacy.** Rows and callouts only. Transcripts and weights stay on this Mac. A row shows the store path. A callout says sessions are not uploaded.

**Usage.** The six Code metrics as `.settings-row`s for the same period set, without a second heatmap.

**Import & export.** Two `.settings-plain-button`s: **Export sessions**, **Import sessions**. Export writes the SQLite session documents as JSON. Import appends them.

**System.** Rows: app version, uzu version, loaded model, **Open logs**.

**Skills, Connectors, Plugins** in this sidebar open the same panes as Customize, inside the settings main column, so the modal does not invent a second list.

## Motion and focus

Keep the prototype’s focus ring (`--focus`), `aria-expanded`, `aria-pressed`, `aria-current`, and Escape order: settings, then menus, then the sidebar drawer, then search, schedule, skill dialog, then the inspector. Send buttons use the existing ready style once the field has text.
